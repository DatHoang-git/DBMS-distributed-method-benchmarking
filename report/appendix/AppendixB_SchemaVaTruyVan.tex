Phụ lục này cung cấp cấu trúc JSON mẫu khớp chính xác với các tệp dữ liệu \texttt{encounters.jsonl.gz} thực tế đã sinh (gồm $9$ trường gốc) và mã truy vấn MongoDB hoàn chỉnh của ba truy vấn đọc đại diện \texttt{Q1}, \texttt{Q3}, \texttt{Q4}.

\section{Cấu trúc JSON Thực tế của Tài liệu \texttt{encounters}}

Kịch bản \texttt{build\_datasets.py} chuyển đổi dữ liệu gốc từ Synthea CSV sang cấu trúc $9$ trường minh họa tại Đoạn mã~\ref{lst:encounter-schema} (trung bình $1{,}273.6\text{ B}$ JSON và $1{,}374.3\text{ B}$ BSON trên \texttt{D3M}). Khi nạp bằng \texttt{load\_dataset.py}, hai trường \texttt{START} và \texttt{STOP} được chuyển đổi sang kiểu ngày giờ nhị phân \texttt{ISODate}. Trước khi nạp, \texttt{prepare\_v2.py} sắp xếp tăng dần các tài liệu theo \texttt{START} trong từng gói tăng dần (\texttt{data/load\_v2/}) để mô phỏng thứ tự ghi thời gian thực.

\section{Mã Truy vấn MongoDB cho Bộ Ba Truy vấn (\texttt{Q1}, \texttt{Q3}, \texttt{Q4})}

Đoạn mã~\ref{lst:queries-q1-q4} trình bày cú pháp MongoDB chính xác của ba truy vấn đọc được thực thi đồng nhất bởi \texttt{bench\_v2.py}.

\begin{lstlisting}[language=MongoJS, caption={Định nghĩa mã MongoDB của ba truy vấn đọc đại diện (\texttt{Q1}, \texttt{Q3}, \texttt{Q4}).}, label={lst:queries-q1-q4}]
// Q1: Toan bo lich su kham cua 1 benh nhan (dung cho RQ1 va tai su dung cho RQ3)
db.encounters.find(
  { PATIENT: pid },
  { START: 1, ENCOUNTERCLASS: 1, ORGANIZATION: 1, conditions: 1 }
).sort({ START: -1 })

// Q3: Top 10 ma benh pho bien trong 1 quy (xuyen benh nhan, ket qua nho = 10 dong)
db.encounters.aggregate([
  { $match: { START: { $gte: qStart, $lt: qEnd } } },
  { $unwind: "$conditions" },
  { $group: { _id: "$conditions.CODE", n: { $sum: 1 } } },
  { $sort: { n: -1 } },
  { $limit: 10 }
])

// Q4: Luot kham danh gia thuoc (ma 314529007) trong 1 thang (xuyen benh nhan, ket qua lon)
db.encounters.find(
  { "conditions.CODE": "314529007", START: { $gte: mStart, $lt: mEnd } },
  { PATIENT: 1, START: 1, ORGANIZATION: 1 }
)
\end{lstlisting}
